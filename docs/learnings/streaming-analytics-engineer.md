# Streaming analytics engineer learnings

## Active
- [mistake] 2026-10-23 A live tracking frame at t that looks ahead D seconds must use one fixed time base and a binary-searched event horizon t+D at every simulation step, including perceived/reaction snapshots. Floating-point step rounding can build a step beyond the currently published horizon; snap near-grid sample requests before ceil. (streaming-analytics-engineer)
- [work] 2026-10-23 Generated comeback seed 42 has event actor coordinates that cannot be reached from the three-second lookahead at a 9.5 m/s cap: even the optimistic top-speed-plus-5m bound makes only 483/983 actor events reachable. Do not improve an actor-hit metric by teleporting players or looking beyond the published horizon. (streaming-analytics-engineer)
- [mistake] 2026-10-23 Clamping a projected tracking clock to a once-per-second raw service clock prevents unpublished-event leakage but produces duplicate 5 Hz frames between service ticks. Report distinct advancing frames separately from SSE message frequency and retain a test of publish-clock equivalence. (streaming-analytics-engineer)
- [mistake] 2026-10-23 Draining the final three simulated tracking seconds after a match ends changed when the SSE closes. The HTTP route test still advanced its fake scheduler only 0.6 seconds past the clock end, so its stream read timed out; always update lifecycle tests alongside a terminal-drain policy. (streaming-analytics-engineer)
- [mistake] 2026-10-23 In a whole-suite parallel run a single 90.62 ms tracking-build sample failed an 80 ms worst-call assertion even though the p95 SLO passed. A GC/scheduler interruption is not an algorithmic latency regression; gate normal latency with p95 and retain a loose catastrophic tail bound. (streaming-analytics-engineer)
- [mistake] 2026-10-24 A live service's wall-clock ticker (view.clockSecond) is not a received-event watermark: under an event-loop stall it runs ahead of the separate publish timers, and the forward-only tracking cache then keeps frames built with missing events (115 m live vs replay at speed 60). Gate the tracking horizon on a receipt-based watermark (every feed entry due <= S accepted by the consumer), and build no frame at all until the watermark covers the lookahead, since a t=0 frame from an empty feed poisons the whole cached timeline. (streaming-analytics-engineer)
- [mistake] 2026-10-24 Any position clamp applied after the velocity/acceleration limiter re-introduces teleports and 36-150 m/s^2 spikes. Apply depth limits to the target, brake toward bounds with the discrete-time safe speed v = -a*dt + sqrt((a*dt)^2 + 2*a*room) using a budget below the limiter's accel, and keep only a hard clamp whose correction is itself step-capped. Measure step and accel from emitted frames. (streaming-analytics-engineer)
- [work] 2026-10-24 Replay-equality tests must rebuild the reference on a fresh tracking cache key (e.g. fixture id + '-replay'); same-key replays read the live-built cached timeline and hide divergence. (streaming-analytics-engineer)

- [mistake] 2026-10-24 A crowd cap on tracking targets alone left near-ball p90 at 4: positions trail targets by the reaction delay (0.5-1.5 s), the target EMA and a 0.42 base movement scale, so displaced players linger in the ring. Re-read the current snapshot target with no delay and a short tau for any player inside the ring whose target is outside it (a "clear-out"); measure crowding from emitted frames, not targets. (streaming-analytics-engineer)
